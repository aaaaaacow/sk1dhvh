# Lua: быстрый старт

**English:** [lua-guide.en.md](lua-guide.en.md)

Этот документ — инструкция для авторов скриптов HvH. Полный список функций, событий и лимитов: [lua-api.md](lua-api.md).

## Загрузка

1. Открой меню → **Config**. Lua находится справа от конфигов.
2. Вставь содержимое `.lua` в редактор, укажи имя и нажми **Load / reload**.
3. Собственные контролы скрипта появятся ниже кнопок Lua — прокрути правую колонку.
4. **Save source** сохраняет исходник в личном профиле. После входа скрипт нужно загрузить вручную.
5. **Unload** убирает рисунки, 3D-эффекты, callbacks и overrides скрипта.

Значения созданных Lua-контролов автоматически в профиль не сохраняются. `storage` сохраняет данные между reload в текущей игровой сессии, но не между заходами.

## Два готовых примера

| Файл | Что делает | Что включено сразу |
| --- | --- | --- |
| [starter-hud.lua](lua-examples/starter-hud.lua) | Отдельный FPS-счётчик, график времени кадра или фигуры; выбор **Element**, настройка цвета | FPS-счётчик |
| [starter-hitlog.lua](lua-examples/starter-hitlog.lua) | Свои подтверждённые попадания/промахи, hitgroup, урон, оставшееся HP, kill; опциональные настоящие 3D-трейсеры | Хитлог и трейсер своих выстрелов |

Хитлог появляется после выстрела, а не сразу после загрузки. Он не включает rage и не меняет параметры стрельбы. Сообщение о промахе возможно только для выстрела с rage-целью и доступным серверным результатом; для обычной пули мимо цели не придумывается причина.

## Строение скрипта

```lua
local enabled = ui.new_checkbox('My script')
ui.set(enabled, true)

client.set_event_callback('paint', function()
    if not ui.get(enabled) then return end
    renderer.text(30, 100, 255, 255, 255, 255, 'hello', 18)
end)
```

Контролы, PNG-текстуры и callbacks создавай один раз, при загрузке. В `paint` рисуй нужный кадр заново: не нарисованный в новом кадре элемент скрывается. Не создавай checkbox или не декодируй PNG в `paint`.

Контролы по умолчанию появляются в Config > Lua. AA-билдер (или любой другой скрипт) может забрать вкладку себе: `ui.override_tab('AA')` — встроенные группы прячутся, контролы скрипта встают на их место, разложенные по группам через `ui.set_group(id, 'Builder')`. Встроенные настройки при этом продолжают работать, после Unload вкладка возвращается как была. Пример — `lua-examples/aa-builder-extended.lua`.

## Какое событие выбрать

| Задача | Callback |
| --- | --- |
| Панель, индикатор, ESP, анимация | `paint` |
| Рисование после обычного paint, в том числе в меню | `paint_ui` |
| Реальный выстрел и его результат | `shot` |
| Подтверждённое попадание; источник известен | `player_hurt` |
| Свой rage попал / промахнулся | `aim_hit` / `aim_miss` |
| Новое публичное состояние игроков | `net_update_end` |
| Смена раунда / состояния бомбы | `round_start`, `round_end`, `bomb_*` |
| Свои углы и desync | `anti_aim` |
| Настройки rage на текущий вызов | `rage_config` |
| Отсев/приоритет цели, записи или точки | `rage_target`, `rage_record`, `rage_point` |
| Последний запрет подготовленного выстрела | `rage_fire` |
| Собственная гипотеза корпуса цели | `resolve` |
| Визуальная камера | `override_view` |

`aim_fire` — предсказанное намерение выстрелить; оно не доказывает попадание. Для хитлога бери серверный `shot` или `player_hurt`. Snapshot-события имеют `observed=true`: промежуточное состояние могло не попасть в полученный пакет. Урон от падения/бомбы виден через `player_health`, без выдуманного attacker.

Таблицы игровых данных — копии. Их изменение не меняет игру. Изменяемые callbacks работают только через перечисленные в API поля: например `c.yaw` в `anti_aim` или `v.fov` в `override_view`. Для выбора своей гипотезы `resolve` возвращает угол.

## Координаты, цвета и время

- Экранные координаты и толщина 2D-линий — пиксели.
- Мировые координаты, размеры 3D-эффектов и ширина трейсеров — **hu**, 12 hu = 1 Roblox stud.
- `vector.new(x,y,z)` создаёт Vector3; вертикальная ось — Y.
- Цвет — RGBA 0…255, alpha255 полностью непрозрачна.
- Углы — градусы, FOV камеры — горизонтальный.
- `globals.realtime()` подходит для локальных анимаций/затухания; `globals.curtime()` — серверное время.
- `globals.frametime()` — секунды: для миллисекунд умножь на1000.

## Настоящие 3D-трейсеры

```lua
client.set_event_callback('bullet_impact', function(e)
    if e.shooter ~= entity.get_local_player() then return end
    if (e.impact - e.start).Magnitude <= .001 then return end
    renderer.tracer(e.start, e.impact, {
        color={125,209,255,255}, width=2,
        end_width=.5, life=1, fade=.3, glow=1,
    })
end)
```

Это engine Beam в мире, с обычным перекрытием геометрией. Создавай один раз по событию, а не каждый `paint`. Срок жизни и cleanup обрабатываются автоматически. Цветное свечение не означает автоматическое включение Bloom. Встроенный PNG-handle нельзя передавать в `texture` у Beam: для текстур Beam используется доступный игре `rbxassetid://`.

## Картинки

```lua
local logo = renderer.load_png_base64('...ваш Base64 PNG...')
client.set_event_callback('paint', function()
    renderer.texture(logo, 30, 100, 128, 64, 255,255,255,255)
end)
```

Строка выше — схема, не готовый валидный PNG. Рабочий пример есть в `hysteria-image-test.lua`. Белый tint сохраняет исходные цвета. Поддерживаются PNG/RGBA; JPEG/SVG и interlaced/16-bit PNG не поддерживаются. Загружай картинку один раз; последующие кадры используют handle. При unload движок освобождает память.

## Производительность

Рисуй только нужное, держи списки логов/точек ограниченными, удаляй истёкшие записи. Для графика заранее создай буфер фиксированной длины. Тяжёлые подсчёты запускай по snapshot/таймеру, а не повторно на каждую линию. `rage_point` может вызываться много раз — callback должен быть коротким.

| Ограничение | На скрипт |
| --- | --- |
| Исходник | запуск до 400 KiB, сохранение до 192 KiB |
| 2D-примитивы | 384 за кадр |
| Контролы | 48 |
| PNG/RGBA | до256×256,32 текстуры /1 MiB пикселей |
| Активные 3D-трейсеры | 64; до16 новых за кадр |
| Активные 3D-эффекты | 32; до16 новых за кадр; до4 источников света |
| Таймеры | 32; повторяемые с интервалом от.05s |
| world/bullet trace | 128 за кадр |
| Публичные позы | 64 построения за кадр |

Скрипт получает 10 ms работы VM за кадр, загрузка (код вне callbacks) — 2 s. Ошибка или превышение бюджета внутри callback прерывает только этот вызов: скрипт остаётся загруженным, следующий кадр снова вызовет callback, а сообщение показывается в выводе Lua (повторы считаются как `+N more`). Скрипт выключается только при ошибке во время загрузки. Изменения команды и ответы rage hooks из прерванного вызова не применяются. Это не гарантия полной изоляции любой нативной операции.

В ошибке `execution budget exceeded` поле `frame time` означает, что кончились 10 ms кадра, `load time` — 2 s загрузки. `event` показывает событие, `instructions` — число инструкций текущего вызова, `frame` — накопленное время. Время делится между всеми callbacks скрипта, включая повторные вызовы `resolve` и rage hooks за кадр; после исчерпания остальные callbacks этого кадра пропускаются.

Исходник больше ~195 KiB не помещается в одно поле Roblox: вставь первую часть, нажми **Add as part**, вставь следующую и так далее, затем **Load / reload** (части склеиваются по порядку, **Clear parts** их сбрасывает). Скрипт до 400 KiB запускается (больше не выдерживает память компилятора; компиляция 400 KiB занимает несколько секунд), но **Save source** сохраняет только до 192 KiB: больший скрипт работает до выхода из игры, потом его нужно вставить снова.

Ошибки показываются как `line 12 (draw): attempt to index nil with 'x' [from line 30 (paint_esp) <- line 41]`: сначала строка и функция, где упало, потом цепочка вызовов. Синтаксические ошибки — `line N: ...`.

## Совместимость и частые ошибки

- Частично совместимо с gamesense: `ui.new_*("TAB", "Group", "Name", ...)` (комбобоксы/мультиселекты такого вида читаются и пишутся названиями опций, есть `ui.contains`), `renderer.text(x, y, r, g, b, a, flags, max_width, ...)` с флагами `c r b - +`, `renderer.measure_text(flags, ...)`, `renderer.circle(..., radius, start, percentage)`, `circle_outline`, `indicator`, `client.key_state(0x41)` (виртуальные коды клавиш), `client.color_log/random_int/random_float/unix_time/system_time`, `globals.absoluteframetime/mapname/maxplayers`, `entity.get_prop` с `m_iHealth/m_ArmorValue/m_fFlags/m_vecOrigin`, `require "vector"` (gamesense-вектор) и `require "bit"`. Неизвестные события (`run_command` и т.п.) игнорируются, их список виден после загрузки. FFI, `require "gamesense/..."` и `ui.reference` по названиям меню gamesense недоступны — для настроек используй ключи из `ui.list_settings()`. Нет настоящих `game` / `workspace`, remotes и произвольных Instances; HTTP (`game:HttpGet`, `request`, `http.*`), файлы (`readfile` / `writefile`...), `task.*` и `loadstring` есть — см. lua-api.md.
- Комбобоксы имеют индексы **с1**. `ui.get(color)` возвращает четыре числа, а не Color3.
- Ошибка в callback не выключает скрипт, но этот вызов обрывается; смотри строку вывода под Lua. Ошибка при загрузке скрипт выключает.
- Есть привычная стандартная библиотека: `string.gsub/gmatch/find/match/format`, методы строк (`s:sub()`, `s:gsub()`), `os.clock/time/date`, `setmetatable/getmetatable` (классы через `__index`), `rawget/rawset`, `_G`, `coroutine`, `utf8`, `table.move`, `bit.tobit/tohex/arshift/rol/ror`, `math.modf/log10/noise`, `collectgarbage("count")`. Таблицам, которые передаёт игра (аргументы событий, `entity.get` и т.п.), метатаблицу поставить нельзя — скопируй поля в свою таблицу.
- `world_to_screen` может вернуть nil — проверяй перед рисованием.
- Нет логов без выстрелов — это нормально. События не воспроизводятся задним числом после Load.
- Реальные закрытые углы противника недоступны. `resolve` — предположение; `trace_bullet` — идеальная оценка, не гарантия реального попадания.
- Камера меняет изображение, а не направление серверной стрельбы.
- Перед проверкой нового скрипта выгрузи предыдущую версию. Overrides нескольких Lua складываются; последняя допустимая запись имеет приоритет, unload возвращает предыдущее значение.

## Защита своего кода

От кражи исходника не защищён никто: любой код, который работает на клиенте, экзекутор может выдрать из памяти. Но это можно сильно усложнить. Прогони скрипт через обфускатор (Prometheus, luaobfuscator, MoonSec, Luraph...) и опубликуй результат кнопкой **Publish sealed**: исходник останется у тебя, остальные получат по коду только байткод без имён переменных и номеров строк. Подробности — в lua-api.md, разделы «Закрытые скрипты» и «Защита кода от копирования».
